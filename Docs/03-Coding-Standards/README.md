# 03 Coding Standards

## Core Principles

- Preserve the existing static build pipeline unless an approved decision changes it.
- Prefer small, inspectable changes over broad rewrites.
- Use the existing page, route, and schema patterns before adding new abstractions.
- Keep content generation deterministic where possible.
- Make validation easy to run locally and in CI.

## Repository Rules

- Source pages currently use `*-gpt.html` naming.
- Clean public routes are generated by `tools/build-cloudflare-preview.py`.
- Generated output lives in `cloudflare-preview/` and should not be committed.
- Static assets should live under `assets/` with descriptive names.
- Data-backed content should use `data/` when it needs to be reused by the build.

## Build Rules

Use:

```powershell
cmd /c npm run build:cloudflare
```

PowerShell may block `npm.ps1` on this machine, so `cmd /c` is the safer local invocation.

Production build:

```powershell
cmd /c npm run build:production
```

## Validation Rules

When routes or links change, run:

```powershell
python seo-automation\scripts\check_internal_links.py --root cloudflare-preview --out tracking\internal-link-report-cloudflare-preview.md --canonical-domain www.sunray-cleaning.com --canonical-domain sunray-cleaning.com
```

When Python build code changes, run:

```powershell
python -m py_compile tools\build-cloudflare-preview.py
```

## Diff Rules

Before committing:

- Review `git diff --stat`.
- Review `git diff --cached --stat`.
- Check for unrelated files.
- Do not stage unrelated dirty files.
- Confirm generated files are not staged unless they are meant to be tracked.

## Code Quality

- Keep generator code explicit and readable.
- Avoid one-off string hacks when a reusable route metadata structure would be clearer.
- Use structured data objects before serializing JSON-LD.
- Escape HTML output when injecting generated labels, URLs, or copy.
- Keep comments rare and useful.
