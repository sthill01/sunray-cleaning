# Roadmap

Version: 2.1

Last Updated: 2026-06-30

This file is the daily-read roadmap. The expanded roadmap lives in `docs/roadmap/README.md`.

## Current Milestone: Operational Readiness

Operational Readiness is Phase 0. It is complete when:

- Every decision has a documented home.
- Every sprint leaves the repository in a better state.
- Codex always knows what to do next from `NEXT_ACTION.md`.
- Steve is asked only for true external blockers.
- Project state, blockers, ideas, opportunities, technical debt, AI monitoring, backlog, and sprint history are durable in `docs/`.
- The end-of-sprint engineering review loop is active.

## Program Phases

### Phase 0: Operating System

- Create and maintain the flat `docs/` cockpit.
- Keep `PROJECT_STATE.md` and `NEXT_ACTION.md` current.
- Establish blocker, idea, opportunity, technical debt, and AI monitoring logs.
- Make every sprint self-documenting.

### Phase 1: Technical Foundation

- Harden Cloudflare Pages build validation.
- Improve route, sitemap, robots, canonical, and `llms.txt` confidence.
- Create route and content inventory automation.
- Add schema, metadata, link, and image coverage reporting.

### Phase 2: Entity Authority

- Define service-area and service taxonomy.
- Strengthen brand, location, service, property-type, review, and guide relationships.
- Make the best citation page obvious for every important AI prompt family.

### Phase 3: Knowledge Graph

- Connect services, locations, neighborhoods, guides, images, reviews, FAQs, and quote paths.
- Generate internal-link opportunities from structured route metadata.
- Improve crawl paths and answer-engine extractability.

### Phase 4: Service-Area Expansion

- Build useful city, county, neighborhood, resort, and property-type coverage.
- Prioritize pages with real business relevance and authority value.
- Avoid interchangeable local doorway pages.

### Phase 5: Content Engine

- Create reusable page templates, briefs, QA checklists, and publishing workflows.
- Maintain content inventory and gap reports.
- Support controlled generation without inventing facts.

### Phase 6: Review and Trust Intelligence

- Keep review data synchronized.
- Use approved review excerpts safely.
- Improve trust sections and review schema where accurate.

### Phase 7: Image SEO

- Improve image names, alt text, captions, metadata, and image schema.
- Prefer real job photos where available.
- Report image coverage gaps.

### Phase 8: Analytics

- Define KPIs for leads, quote starts, conversion paths, content health, and AI visibility.
- Build dashboards once data access exists.
- Separate measured facts from proxy indicators.

### Phase 9: Automation

- Automate recurring audits.
- Add CI-ready checks where practical.
- Reduce manual SEO and QA repetition.

### Phase 10: AI Monitoring

- Track ChatGPT, Claude, Gemini, Grok, Perplexity, and Google AI Overviews prompts.
- Record Sun Ray visibility, competitor mentions, citation sources, and changes over time.

## Near-Term Priority Stack

1. Finish Operational Readiness docs and commit the cockpit.
2. Build route and content inventory automation.
3. Build schema, metadata, and internal-link coverage reports.
4. Create an entity taxonomy for services, locations, property types, and prompt families.
5. Create the first AI monitoring prompt set and baseline report.

## Backlog Intake Rule

New work should enter `BACKLOG.md` with:

- Problem.
- Proposed outcome.
- Impact.
- Effort.
- AI authority gain.
- Revenue potential.
- Risk reduction.
- Automation leverage.
- Validation method.
